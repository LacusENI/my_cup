# 演进路线图

本文给出 `my_cup` 的下一步演进建议，按**风险从低到高、依赖从先到后**分阶段组织。
中期主线是 **单周期 → 5 级流水线**，因此阶段 0/1 的目标是为流水线**扫清障碍**，而不是无谓地堆功能。

> 背景与现状见 [architecture.md](arch/architecture.md)。

---

## 总览

| 阶段 | 主题 | 目标 | 优先级 |
| :-- | :-- | :-- | :-- |
| 0 | 工程基建 | 让改动可回归、可检查 | ★★★（先做） |
| 1 | 补全单周期 | 补齐半成品、清理控制逻辑 | ★★★ |
| 2 | **单周期 → 流水线** | 5 级流水 + 冒险处理 | ★★★★（主线） |
| 3 | 能力扩展 | 异常/CSR、总线、更多指令 | ★★ |
| 4 | 验证与对标 | 随机测试、RVFI/对标、覆盖率 | ★★ |

建议顺序 **0 → 1 → 2**，阶段 3/4 可与 2 并行推进。

## 明确延后（Deferred）

以下内容**不在当前 ISA**，等内存子系统定型后再一起做：

- **子字访存**：`sb/sh/lb/lbu/lh/lhu`；
- **端序策略**：大端/小端（整字访问下不影响功能）；
- **字节掩码**：core → memory 的 `wstrb[3:0]`；
- **DM controller / 总线**：Wishbone/AXI-Lite 简化接口、Cache；
- **更多指令**：逻辑/移位/比较、更多分支、异常/CSR。

> 理由：这些改动会同时影响 DM、控制通路、测试与端序，过早实现容易返工。

## 阶段 2 · 单周期 → 5 级流水线（主线）

### 2.1 目标形态

经典 **IF / ID / EX / MEM / WB** 五级：

```
IF ──► ID ──► EX ──► MEM ──► WB
取指   译码  执行   访存   写回
```

数据通路本身**基本不变**（各功能单元已被清晰切分），主要新增的是**级间流水寄存器**与**冒险处理**。

### 2.2 关键改造点

**(a) 插入流水寄存器**（建议新建 `rtl/core/pipe/`）

| 寄存器 | 携带内容（示意） |
| :-- | :-- |
| `IF/ID` | `pc_plus4`、`instr` |
| `ID/EX` | 读出的 `rs1/rs2 数据`、`imm32`、`rs/rt/rd`、**全部控制信号** |
| `EX/MEM` | `alu_out`、`rs2 数据`(写内存用)、目标寄存器号、`MEM/WB` 相关控制 |
| `MEM/WB` | `r_data`、`alu_out`、`pc_plus4`、`wb_sel`、`reg_dst`、`reg_write` |

> 核心原则：**控制信号必须与它对应的数据在同一级被同步打拍**，否则会出现"控制信号跑到数据前面"的经典 bug。

**(b) 数据冒险（RAW）**

- **前递（forwarding）**：`EX` 的操作数可从 `EX/MEM`（上一条的 ALU 结果）或 `MEM/WB`（写回值）旁路过来；
- **load-use 停顿**：`lw` 后紧跟使用其结果的指令，需停顿 1 拍（无法纯前递解决）；
- 引入 `hazard.v` 统一产生**前递选择**与**停顿/冲刷**信号，避免散落在顶层。

**(c) 控制冒险**

- 分支若在 `EX` 级判定，需要**冲刷 `IF/ID`、`ID/EX` 两级**（插入 2 个气泡）；
- 可选优化：把分支判定与目标计算**提前到 `ID` 级**（加一个比较器 + 小加法器），只需冲刷 1 级；
- MIPS 传统做法是**分支延迟槽**，但你现有测试是"顺序语义"，若引入延迟槽需同步调整测试与文档——建议初期用 **flush（预测不跳转）**，语义更直观。

**(d) 结构冒险**

- **已天然规避**：`instrm` 与 `datam` 是两个独立存储体（哈佛结构），取指与访存不冲突；
- 需处理 `regfile` 的**同拍写读**：让寄存器堆"先写后读"（write-first）或利用半周期时序，保证 `WB` 写与 `ID` 读不冲突。

### 2.3 迁移策略（二选一）

| 方案 | 做法 | 优点 | 风险 |
| :-- | :-- | :-- | :-- |
| **A. 一次性重构**（推荐） | 新建 `pipe/` 流水寄存器 + 新 `cpu_top`，把现有单元按级重新连接 | 结构干净、一次到位 | 改动面大，需保证单元不变 |
| B. 增量拆分 | 先加 `IF/ID` 与 `ID/EX` 得到 3 级，跑通后再拆到 5 级 | 每步可回归 | 中间态多、反复改连线 |

> 建议 **A**：因为**功能单元（`alu/ext/cond/regfile/datam/...`）几乎无需改动**，重构集中在 `cpu_top` 与新增流水寄存器；只要阶段 1 已把控制逻辑集中、默认值清理干净，一次性重构的可控性反而更高。

### 2.4 验证重点（新增专用测试）

- **RAW 前递**：连续 `addu` 依赖链，检查是否多/少打拍；
- **load-use**：`lw` 后立即用其结果的停顿行为（验证恰好 1 拍气泡）；
- **分支冲刷**：`beq` 已流入的后续指令应被正确丢弃，`$ra`/PC 不被污染；
- **写读冲突**：`WB` 写与 `ID` 读同一寄存器时读到新值。

> 建议为每条指令保留一份**单周期黄金参考**（现有 testbench 可直接复用），流水线版本运行**相同程序**，用寄存器/内存终态做**差分对比**，比逐信号波形更快定位问题。

### 2.5 常见坑

- 控制信号未随数据打拍 → 用错控制（最典型）；
- 忘记冲刷时 `reg_write` 仍有效 → 误写寄存器；
- `$0` 恒零在读/写两条路径都要保护；
- 跳转目标中 `curr_pc` 的取用级：`j` 的目标依赖当时的 PC，需用 `IF/ID` 中保存的 `pc` 而非最新 `curr_pc`。

### 2.6 后续（阶段 2 之后的热点）

- **分支预测**：`BTB`（分支目标缓冲）+ `BHT`（2 位饱和计数器）替代"预测不跳转"，进一步减少冲刷；
- 每级的**流水线寄存器重定时**（retiming）以缩短关键路径。

## 阶段 3 · 能力扩展

- **异常/中断/CSR**：引入 `mepc/mcause/mstatus` 等，支持 `ecall/ebreak` 与中断入口。
- **存储/总线接口**：把 `instrm/datam` 抽象为统一的**总线接口**（如类 Wishbone/AXI-Lite 的简化握手），便于接外部内存模型或 FPGA BRAM。
- **Cache**：为访存加一级 Cache（正好可检验流水线在停顿下的正确性）。
- **压缩指令 / 更多扩展**：视目标 ISA 而定。

---

## 阶段 4 · 验证与对标

- **随机指令生成**：随机构造指令流并与**参考模型**（如用 C/Python 写的 ISS，或 Spike/rv8）逐步比对。
- **RVFI / 追踪接口**：暴露"每退休一条指令的 (pc, instr, rd, wdata, ...)"，让差分测试自动化。
- **覆盖率**：用 Verilator coverage 收集行/翻转/功能覆盖率，驱动补齐测试。
- **形式化（可选）**：对 `alu/cond` 等纯组合单元做等价性检查（SAT/等价工具）。
